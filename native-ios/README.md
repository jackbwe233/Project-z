# Project Z — Private iPhone app (native build preparation)

This folder prepares the existing Project Z website as a **Capacitor iOS app**. It does not change the live GitHub Pages website, publish anything to the App Store, or include signing credentials.

## What you need

- A **Mac** with Xcode 26+ and an up-to-date iOS SDK
- Node.js / npm
- Your own Apple Account (free Personal Team is sufficient for on-device testing)
- Your iPhone, connected to the Mac; enable Developer Mode if prompted

**If you only have an iPhone right now:** Safari > Share > Add to Home Screen remains the easiest working installation. Compiling and signing a native iOS app is not possible from the iPhone alone using these steps.

## Build on a Mac

From the Project Z repository root:

```sh
cd native-ios
npm install
npm run ios:init
npm run ios:open
```

In Xcode, select the **App** target, choose **Signing & Capabilities**, enable **Automatically manage signing**, and choose your Apple Account's **Personal Team**. Connect and select your iPhone, then press **Run**.

For every new version of the website code:

```sh
cd native-ios
npm run ios:sync
npm run ios:open
```

Capacitor packages local copies of site files in `www/` (generated by `prepare-web.mjs`) instead of relying on the public GitHub Pages site for the app shell. Models may still need internet to download and may have browser-origin or WebView restrictions.

## Known blocker to test before calling this a functional native AI app

Project Z's local AI model loading depends on **WebGPU**, persistent browser storage, and browser APIs. iOS **WKWebView** and Safari do not always expose or behave identically for these APIs. Native packaging does **not** fix existing Load Model / silent response issues. Test these on a real iPhone before using a native build as the main Z experience:

1. Open Z and check for WebGPU availability in the app's diagnostics.
2. Load the smallest supported model, send a prompt, and confirm text renders.
3. Force-close and reopen to check that chat and downloaded model caches persist.
4. Test microphone permissions, dictation, audio playback and file upload.
5. Check that optional web search works and reports failures visibly.

If WebGPU or model caching fails inside the native WebView, keep using the Safari Home Screen version until the inference engine is replaced with a native-compatible runtime or a secure, user-approved backend. Do not label the native wrapper as fully functional before testing.

## Important private-install limitations

- **Private installation** means the native app is installed on your own registered device. It does **not** make Project Z's **public GitHub repository and GitHub Pages website** access-restricted.
- Free Apple Personal Team signing expires after **7 days**; rebuild/reinstall with Xcode to continue using the test app.
- Do not commit private keys, API tokens, Apple certificates, or provisioning profiles to GitHub.
- This is a development setup, not a compiled `.ipa` or a tested App Store build.

Official documentation: https://capacitorjs.com/docs/ios and https://developer.apple.com/help/account/basics/about-your-developer-account
